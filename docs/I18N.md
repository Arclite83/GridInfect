# Internationalization

Stage 13 of `EXECUTION_PLAN.md`. The string pipeline, the language setting
and selector with its script marks, the direction-aware chrome, the
TextMeshPro renderer over the vendored faces and their Noto fallbacks,
measured layout, and eleven languages are in. What is left is the
scripts the game does not draw yet (see "Remaining"). This file is the rules any new screen obeys and the list of
what is left, not a description of the code.

## Rules

- **Core holds keys and never prose.** A word a player reads lives in
  `docs/strings/<tag>.json` and is read through `Str` in the adapter. A
  gameplay type carries an id (`w14`, tutorial step 3) and the adapter looks
  the word up (`Str.WorldName`, `Str.TutorialLine`).
- **Every user-facing string is a `Str` property.** `tools/bake_strings.py`
  emits `Game/Strings.g.cs` from `en.json`; a key is a property, so a typo
  is a build error. Substitutions go through `Str.Fmt`, bare numbers through
  `Str.Num`; both are invariant, because every number the game shows is a
  mono-column readout and the device's digits would break the column.
- **Casing is authored in the table.** No `ToUpperInvariant` on display
  text (Turkish; scripts without case). A build hash is not display text.
- **No plurals.** Counts are label-value (`BUGS 3`), the HUD idiom, so no
  language needs plural rules.
- **A string is never a layout.** No literal spacing as columns, no
  `Substring` for a short form (month short forms are their own keys), no
  width from `label.Length`: a box is sized by `Ui.MeasureWidth` and a text
  fits its box by `Ui.FitText`, down to the 11 px legibility floor.
- **Chrome mirrors; the board never does.** Positions come from
  `Layout.Lead`/`Trail`/`ColumnX`, anchors from `Layout.Leading`/`Trailing`,
  pager marks from `BugGlyph.Prev`/`Next`. Board coordinates, arms, tray and
  glyphs never pass through `Layout.Dir`. `Str.IsRtl` drives all of it and
  `qps-plocm` exercises it before any RTL language ships.
- **Language is a BCP-47 tag**, stored in `Profile.Lang` by
  `settings.language`, `""` meaning follow the device. Core validates shape,
  not membership; `Str.Resolve` falls back to the device for a tag that does
  not ship. Never an index, never a mark id.
- **Selector: mono chip carrying the tag, plus a drawn script mark for
  readers who cannot read Latin.** No flags: they name countries, and the
  cases where that breaks (Arabic, the two Chinese scripts) are the ones
  that matter. Marks come through the `gen-logo.mjs` outline pipeline as
  `SelectorGlyphs.g.cs`, so the picker needs no font for a script it offers.
- **One tag per language.** No two regional variants ship together; that is
  what makes a compact selector unambiguous. `pt-BR` because only one
  Portuguese ships and it should say which.

## Pipeline

`docs/strings/en.json` → `python3 tools/bake_strings.py` →
`unity/Assets/_Project/Game/Strings.g.cs`. CI re-derives and fails a stale
bake. The baker itself fails when a `<tag>.json` key set or any `{N}`
placeholder set differs from `en.json`, when a `world.<id>.name` does not
match `docs/worlds/<id>.jsonl` (case aside), or when a `tut.<n>.line` is
empty, breaks, or draws wider than the one-line band (East Asian width, so
CJK counts double). Two pseudolocales are generated, never authored:
`qps-ploc` pads and accents to find clipping; `qps-plocm` reverses to find
left/right assumptions. Both show in the editor and development builds
only.

Two more tools read the Noto sources, which are not in the repo (point
`--fonts` at a folder of them from google/fonts). `tools/subset_fonts.py`
cuts `Resources/Fonts/Fallback-*.ttf` to exactly the code points each
language's strings use that Chakra Petch and Share Tech Mono do not carry,
one face per CJK language because kanji and hanzi share code points and
are drawn differently in Japan, the mainland and Taiwan; `Ui` orders the
fallbacks with the language in force first. Run it after a string file
changes, or a new character draws on the OS face.
`tools/gen_selector_glyphs.py` emits `View/SelectorGlyphs.g.cs`, the
selector's one drawn glyph per non-Latin language.

## Remaining

| Item | Why it waits |
|---|---|
| **Arabic, Hebrew** | Both need shaping the text stack does not do. Hebrew is bidi only; Arabic needs joining, so on TMP it is a preprocessing plugin (RTLTMPro or equivalent) plus Presentation Forms font blocks. Unity's own answer (Advanced Text Generator) is UI Toolkit-only, which this project does not use. The direction rules above are why this stays an addition and not a re-cut |

No alternate build for any market: mainland China is not reachable by a
self-publisher on Google Play and the global App Store regardless, and
script marks keep the question out of the product. The wordmark stays
Latin; it is a logo.
