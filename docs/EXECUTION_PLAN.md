## Standing constraints (every stage)

- `GridInfect.Core` stays pure C#: no `UnityEngine`, no SDK types
  (`noEngineReferences`). The architecture gate tests enforce this; do not
  weaken them.
- Actions are the only writers of state. New capabilities are new actions
  in the registry with validated inputs; never an in-place break of a logged
  action. Wall clock and RNG seeds enter only through action inputs.
- The 128 classic vectors (`docs/test_vectors.json`) must replay unchanged
  at every stage. The classic rules are frozen; new behaviour lives beside
  them, never inside them.
- CI is the mirror suite: `dotnet test src/Tests.Mirror/...` and the derived
  file check. A stage is not done until CI is green on the PR. Run it locally
  before pushing (`dotnet test`, `python3 tools/bake_levels.py`,
  `python3 tools/gen_undo_fixtures.py`).
- `ARCHITECTURE.md` §2 (schema) and §3 (action registry) are amended in the
  same PR as the code they describe.
- No new third-party packages outside stage 6. No asset store content.
- Every generated file has a generator under `tools/` and a CI freshness
  check, like `ClassicLevelData.g.cs`.
- Keep PRs to the stage. Refactors that are not needed by the stage go in a
  note in the PR body, not in the diff.

Reference oracle for stages 1–2: `tools/level_metrics.py` (exact solution
counts). Python is the oracle; C# is the product.

## Stage 1 — Deduction solver and grader

**Goal.** A human-rules solver in Core that (a) decides whether a level is
solvable by deduction alone, (b) emits the deduction trace, (c) grades it.

**Interface** (`GridInfect.Core.Solving`):

```csharp
public enum Tier { LineOwnership = 1, ArmExclusion = 2, PieceCounting = 3, Contradiction1 = 4 }
public readonly struct Deduction { Tier Tier; int Piece; int Cell; /* cells/segments the rule reasoned about */ int[] Evidence; }
public sealed class SolveResult { bool Solved; Deduction[] Trace; Tier MaxTier; int[] TierCounts; int Guesses; }
public static class Deducer {
    // from an arbitrary state: placed pieces respected, board as-is
    public static SolveResult Solve(LevelDef def, PieceState[] placed = null);
}
public static class SolutionCounter {
    // exact; cap to bound time; must match tools/level_metrics.py
    public static int Count(LevelDef def, int cap = 100000);
    public static (int piece, int cell)[] FirstSolution(LevelDef def);
}
public static class Grader {
    public static Grade Grade(SolveResult r); // enum Grade { G1..G6 }, thresholds documented in GENERATOR_V2.md
}
```

Rules are **line-based** (row segments and column segments between
blockers), not cell-based; cell "sole cover" never fires in this game
(NEXT_PASS.md). Direction families are data (`Family[]`), so diagonals in
stage 11 add a table entry, not a code path. Switches and traps: the solver
treats them as blockers for coverage and checks order feasibility on the
final assignment, as the Python oracle does.

**Acceptance.**
- `SolutionCounter.Count` equals `level_metrics.py` for all 128 classic
  levels (a golden file `docs/level_metrics_classic.json` checked into the
  repo, generated by the Python tool, compared in a test).
- `Deducer.Solve` never reports `Solved` on a level whose count is not 1.
- On the 27 unique classic levels, `Solve` returns `Solved` for at least
  20 without `Contradiction1`; report which fail and why in the PR body.
- Whole 128-level run under 2 s in `dotnet test` on CI.
- `docs/GENERATOR_V2.md` §Solver written: rule definitions with one worked
  example each, grade thresholds.
- Delegable: this stage has a closed interface and an exact oracle.

## Stage 2 — Generator v2

**Goal.** Boards that are unique, deduction-solvable, graded, and deduped.

**Pipeline** (`GridInfect.Core.Generation.GeneratorV2`):
1. Sample a solution and carve, as `LevelGenerator` does, with `CarveParams`
   (density curve, min/max active cells, shape bias) instead of the fixed
   roll. Keep `LevelGenerator` untouched for Legacy Free Play replay.
2. Count solutions. While > 1: place one wall (later stages add other
   pruners) at the cell that eliminates the most alternatives while keeping
   the sampled solution valid; give up after `MaxPruneSteps`.
3. Run `Deducer`. Reject unless `Solved` with `Guesses == 0`.
4. Grade. Canonicalise under the board's symmetry group (horizontal flip,
   vertical flip, 180°) with arms remapped; dedupe by canonical hash.
5. Emit `GeneratedLevel { LevelDef Def; Solution; Trace; Grade; Seed; Hash }`.

Deterministic: `GeneratorV2.Generate(GenSpec spec, ulong seed)`; same
inputs, same output, bit for bit. `GenSpec` = element set, piece count
range, target grade, carve params.

**Acceptance.**
- 1000 accepted boards per grade G1–G5 from a fixed seed range in under
  10 min headless; acceptance rate per grade reported in the PR.
- 100% of accepted boards: count == 1, `Solved`, `Guesses == 0`.
- Golden seeds locked in tests (as `GeneratorTests` does today).
- Batch CLI: `tools/gen_levels` (dotnet console in `src/`) writes JSONL.
- `docs/GENERATOR_V2.md` §Pipeline written.

## Stage 3 — Level bake, worlds, Legacy mode

**Goal.** Shipped content structure and the classic set moved aside.

- World schema: `World { Id; Name; Elements[]; LevelIds[] }` baked with the
  levels into `WorldData.g.cs` from `docs/worlds/*.jsonl` by
  `tools/bake_worlds.py`; CI freshness check.
- Launch content: ≥ 12 worlds × 20–25 levels, grades ramping within a world
  and across worlds. Curate order by grade then by trace length. First and
  last two levels of every world flagged `reviewed: true` by a human before
  merge; the PR lists them.
- Progression: solving level N in a world unlocks N+1; finishing a world
  unlocks the next. New actions: `world.load { worldId, index }`,
  `progress.unlockWorld`. Save schema version bump with an expand/contract
  migration and a round-trip test.
- Legacy mode: the 128 behind a menu entry, existing `level.load` path,
  rules untouched, no Lock (stage 5 may enable it), no changes to its tests.
- Level select gains a world layer; presentation measures from
  `PresentationConfig.Layout` as today.

**Acceptance.** Vectors replay; new levels load and solve via their baked
solution in a test; save migration test; worlds JSONL regenerates
identically.

## Stage 4 — Daily and Endless

- `daily.begin { dateUtc, nowMs }`: seed = stable hash of the UTC date,
  `GeneratorV2` with the daily `GenSpec` (rotating element set per weekday
  once elements exist; cardinal-only at launch). Same board for everyone.
- Timer as a stat only: elapsed shown, par = f(trace length, grade),
  personal best per date. Streak counter, `+1 lock every 7` (stage 5 wires
  the grant). `daily.complete { nowMs }` rejects a backward clock.
- Endless: `endless.begin { grade, seed }`, `endless.advance`, no clock,
  streak = solves without a reset. Seed logged so runs replay.
- Remove timed Free Play from the menu; keep its actions and tests for log
  replay compatibility (never break a logged action).
- Friends leaderboard via Play Games Services v2 is **out of this stage**:
  local only. Leave the hook (`IDailyScoreSink`) in `GridInfect.Game`.

**Acceptance.** Two devices, same date, same board (test: two fresh states,
same input, same `LevelDef` hash). Replay test for a full daily run from its
log.

## Stage 5 — Lock tool

- `PieceState.Locked`. `piece.lock { }` action: picks the target per
  NEXT_PASS.md (Deducer's next forced deduction from the player's current
  correct pieces; fallback largest-coverage unplaced piece from the stored
  solution), evicts a player piece on that cell to the tray, places and
  locks. Rejects when wallet is 0 or nothing is left to lock.
- `Rules.FullReset` and undo leave locked pieces placed. Input refuses to
  lift a locked piece. Lock icon and snap animation in `PieceView`.
- Wallet in `Profile`: cap 10, start 5. `locks.grant { amount, reason }`
  action (rewarded ad, streak). Save schema bump + migration test.
- Legacy levels use the stored vector solution as the fallback source.

**Acceptance.** Lock on every launch level from an empty board reaches a
solved state in ≤ piece-count locks (test over the baked set). Lock never
targets a cell that makes the level unsolvable (test: after each lock,
`SolutionCounter.Count ≥ 1` with locked pieces fixed).

## Stages 7–12 — RulesV2 and new elements (post-launch)

Each element is its own stage: rules, generator pruner/carver support,
solver family or rule, shader/view, one world, one daily variant, docs.
`RulesV2` (stage 7) first: undo = restore initial board and re-propagate
placed pieces in index order; new content runs on V2, Legacy on V1;
switch/trap semantics preserved but the repel-queue accumulation quirk is
not carried. Element specs are in `NEXT_PASS.md`; write `docs/RULES_V2.md`
in stage 7 and extend it per stage.

Order: short arms (8), area piece (9), forbidden cells (10), diagonal arms
(11), relay cells (12). Mirror is undecided; do not start it without a
decision recorded in `NEXT_PASS.md`.

## How a session should run a stage

1. Read `NEXT_PASS.md`, this file, `ARCHITECTURE.md`, and the docs the
   stage names. Fetch `origin/main`; branch from it.
2. Restate the stage's acceptance criteria as a checklist at the top of the
   PR body before writing code.
3. Implement. Tests first where an oracle exists. Run CI locally.
4. Amend docs in the same PR. Update the status table above.
5. Open the PR against `main`. Do not start the next stage.
6. If a criterion cannot be met, ship the rest, state exactly what is
   missing and why in the PR body, and leave the status as `Blocked`.
